# qwen-peer v0.5.9

This release requires Sessionbus v0.5.9 (daemon and hub) and pins the Sessionbus Go SDK `v0.5.9`. The version matches core v0.5.9.

**Breaking, a flag day.** The unreleased lane policy field `idle_message` is removed from the protocol and the SDK; message wake is mandatory. This peer requires a v0.5.9 daemon. Peers built with SDK v0.5.7 or earlier are incompatible with it. Upgrade the hub, the host daemons and the product integrations together. Follow the upgrade steps, including the offline lane-row edit, in the [core v0.5.8 release notes](https://github.com/sessionbus/sessionbus/releases/tag/v0.5.8). v0.5.9 has the same runtime as v0.5.8.

This is the first stable release published from this repository. Changes since the combined v0.5.3 release:
- **Interactive wake uses Qwen's native peer inbox.** `qwen-peer` sends authenticated frames to the native inbox, which starts an idle or next turn, and the launcher replaces itself with native Qwen. The resident launcher and its per-launch input, FIFO, defaults and claim files are gone. A `written` receipt means the inbox write completed, not that a model consumed the message; native hold and refuse policy still applies.
- **Integrated interactive launches need a native controller grant.** Create one with `qwen sessions controllers add` and supply its secret as `SESSIONBUS_QWEN_CONTROLLER_TOKEN`. A missing or malformed token is a setup error; the wrapper neither creates nor stores a grant. Bare mode (`--bare` or a truthy `QWEN_CODE_SIMPLE`) is refused, because the native inbox is unavailable there.
- **The extension provides static `SESSIONBUS.md` context instead of an invokable Skill.** Managed lanes and integrated interactive launches load the granted `mcp__sessionbus__sessionbus` tool directly (`alwaysLoadTools:true`). The exact grant is unchanged. See the [Qwen guide](../../qwen/README.md).

`scripts/install-qwen.sh` installs the latest release by default, so it now installs v0.5.9. Pin `SESSIONBUS_VERSION` on hosts that are not yet in their upgrade window.

## Known limitations

- **No supported recovery after an MCP helper loss (I1.7).** Native Qwen 0.24.6 caches the MCP connection. After a `qwen-peer-mcp` helper loss, its `/mcp` status can still show connected, hiding the Reconnect action, and there is no supported recovery. This is a known native limitation. It was not re-run for this release; the dependency update is no evidence that recovery is fixed.
- **Default-mode unattended permission-request cancellation was not observed live.** In the exercised default-mode lane runs, native Qwen 0.24.6 never issued an ACP `session/request_permission`. The wrapper answers such a request with outcome `cancelled` and cannot approve anything, but that handler is verified at the source level only.
