# qwen-peer v0.5.12

This release requires Sessionbus v0.5.9 or newer (daemon and hub) and pins the Sessionbus Go SDK `v0.5.12`. The version matches core v0.5.12. Native Qwen is installed separately and is not pinned.

`scripts/install-qwen.sh` installs the latest stable release by default, so it now installs v0.5.12 and delivers the changes below, which were previously only on `main`. Pin `SESSIONBUS_VERSION` on hosts that are not yet in their upgrade window.

## Changes since v0.5.9

### Interactive delivery uses a launch-private native input file
- `qwen-peer` creates a private launch directory (mode 0700) with an empty input file (mode 0600) under `$XDG_RUNTIME_DIR`, or under the system temporary directory when that is unset.
- It passes the file to native Qwen as `--input-file` and then replaces itself with native Qwen. Each Sessionbus message is appended as one submit record: an idle session takes it as new input, and an active task takes it at its next eligible boundary.
- A `written` receipt means the complete record was appended, not that a model consumed the message. Uncertain appends are not replayed.
- **No native controller grant is needed anymore.** The v0.5.9 requirement to create a grant with `qwen sessions controllers add` and supply `SESSIONBUS_QWEN_CONTROLLER_TOKEN` is gone. A leftover `SESSIONBUS_QWEN_CONTROLLER_TOKEN` is not required, and it is removed from the native environment. The wrapper neither creates nor revokes native grants; any grant you created for v0.5.9 remains yours to keep or remove.
- **Launching through `qwen-peer` is your permission for Sessionbus input in that session.** Input-file messages do not pass through Qwen's peer-messaging policy: if Qwen's peer feature is disabled, or set to hold or refuse, Sessionbus messages still arrive in a `qwen-peer` session. A message still queued when you cancel a running turn returns to the composer unsent.
- **Newly refused integrated configurations:**
  - a caller `--input-file`, which the wrapper owns;
  - the experimental OpenTUI renderer (`QWEN_TUI_RENDERER=opentui`), which does not read the input file.
  - Native `--bare` mode and a truthy `QWEN_CODE_SIMPLE` remain refused.
- **Residue:** until a later managed launch removes it (after both the recorded native TUI and its supervisor have ended), the launch input file keeps the delivered message text. Whether the runtime directory is cleared at logout depends on the host.

See [the Qwen guide](../../qwen/README.md) for the full rules.

### Managed lanes
- An active lane owns its delivered input, and native Qwen pulls it at its next tool boundary (`craft/drainMidTurnQueue`). Input still owned when the prompt ends continues the same Run.
- A Run continues only after a clean native end.
- Delivery and pulls are bound to their Run and stop at interrupts.
- A lane Run's joined answer stays within the output bound.

### Sessionbus Go SDK v0.5.12
- The SDK's only production change is a new error answer when a product's interrupt callback fails. Qwen's interrupt callback always returns success, so that path cannot occur for this peer.
- The wire protocol is unchanged, so Sessionbus v0.5.9 or newer still suffices.

## Evidence
Nothing was re-run for this release. The evidence is retained from the permanent Linux development host on 2026-10-10, on the same runtime source as this release:
- qwen-peer `c550d0b9`, Sessionbus daemon v0.5.11, native Qwen **0.25.0**;
- four core cases, **one trial each, with `--yolo` / bypassPermissions only**, all PASS: lane idle, lane busy (native mid-turn pull), interactive idle, and interactive busy (input-file carrier).

The README's installed-validation paragraph describes the earlier v0.5.9 evidence.

## Known limitations
- **No macOS live validation.** The macOS process-identity code changed in this release; the evidence above is Linux only.
- **No default-mode or normal-permission trial.** Only `--yolo` / bypassPermissions was exercised.
- **Default-mode unattended permission-request cancellation was not observed live.** The wrapper answers such a request with `cancelled` and cannot approve anything; that handler is verified at the source level only.
- **No supported recovery after an MCP helper loss (I1.7).** This is a native limitation, not re-run.
- **No native cancel or interrupt-error-path claim** beyond the SDK note above. There is no repeated-trial or cross-version matrix; native 0.25.0 compatibility is shown only at the scope above.
