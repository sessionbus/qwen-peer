# qwen-peer v0.5.13

This release requires Sessionbus v0.5.14 or newer on the daemon and every involved hub. It pins the released Go SDK v0.5.14 and shared support at `29ddcb4585de`. Native Qwen is installed separately and is not pinned. The native extension's independent version remains 0.4.0.

## File transfers

Managed interactive sessions and lanes expose the complete shared 18-action Sessionbus tool, including `transfer.offer`, `transfer.request`, `transfer.accept`, `transfer.cancel` and `transfer.status`. Each interactive owner has one SDK transfer manager; lanes use the existing Worker Caller. Offers and terminal notices follow the existing input-file or lane delivery path. Machine traffic stays off the native input path, and local terminal projection runs before the ordinary notice is submitted.

Relative local paths require a known absolute native directory. Interactive actions capture the current cwd observed in the existing native registry; lanes use their native launch directory. Paths are prefixed without cleaning symlink/`..` spelling. Local source and destination paths stay at their endpoint rather than going to the daemon or hub.

Transfers use the SDK's direct filesystem access as the OS user. There is no sandbox or native approval per path. Tightening transfer permissions later is OPEN and is not a release gate. The existing Sessionbus tool grant and native permission handling are unchanged.

Reconnect and final shutdown join owned SDK generations. Cancellation before a notice's local projection is complete gives the existing rejected/"not connected" receipt without a native append; failed or uncertain actual appends keep their existing error and are not replayed. The native input-file carrier, receipt meaning, single-append limit and no supported helper-loss recovery are unchanged. No controller grant, executor policy, retry or durable recovery is added.

## Evidence and retained limits

The existing build, test, race, vet, lint and archive checks are used, together with bounded wiring controls: old capability refusal, native registry cwd changes with a real symlink/`..` source, actual SDK/default-filesystem destination publication, off-reader terminal projection with later ordinary input progress, cancellation before native append, and owned temporary-file cleanup at End. These use the existing native-registry/process/input-file fixture and strict production wire codec, not a model or complete hub transport. The lane unit control checks identity/invocation/binding boundaries before an unsupported caller and does not inspect a transfer manager's resolved path or establish lane I/O.

Native U-series transfers and permanent-install idle wake, busy steer and lane Run are separate required acceptance on UMKA. Source and local checks alone make no native, model, full-matrix or readiness claim; actual results are bound in the final review and release records. The [v0.5.12 evidence and limits](v0.5.12.md#evidence) remain attributed to their exact earlier build/native version and bypass-only cases, including no macOS live, normal-permission, repeated-trial or cross-version matrix. The [Qwen guide](../../qwen/README.md) retains the native input-file and lifecycle rules.
