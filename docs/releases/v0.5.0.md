# Sessionbus peers v0.5.0

This is the first stable binary release of the standalone peers repository.
Claude, Codex, Grok, Qwen, OpenCode and Kilo are the established integrations.
Pi and OMP are included as **preview integrations**; the stable release label
does not remove that qualification.

Requires Sessionbus **v0.5.3 or later** and an installed, authenticated native
product. Sessionbus daemon and peers release numbers are independent. DSH has
its own package and release lifecycle and is not one of these eight archives.

## Included changes

- Managed interactive launches and daemon-owned lanes use the public Sessionbus
  API for discovery, delivery, Run, collection, acknowledgment and cleanup.
- Claude, Codex, Grok, Qwen, Pi and OMP interactive presence reconnects after daemon
  loss while preserving the native session. Old actions and deliveries are never
  replayed. Supersession and native exit remain terminal; Worker lanes retain a
  single launch-connection lifetime.
- Tool declarations expose the protocol's closed argument fields. `send` uses
  `message` and `target`, `targets` or `group`; it has no `summary` field.
- Claude interactive delivery restores the structured envelope for its compact
  sender display. Claude's own model-input guidance remains native.
- Shipped skills explain uncertain `no_receipt` outcomes, lane-only `running`
  state, and which product's options govern cross-product delegation.

## Install and update

Use the [README installer commands](../../README.md#install).
They install the latest stable release and verify the CI-generated archive
checksum. The same commands update an existing installation; they need no
version edits. `SESSIONBUS_VERSION=development` selects the rolling prerelease,
and explicit release tags and mirrors remain supported.

Archives are available for Linux and macOS on amd64 and arm64. Native products,
credentials, permissions and configuration remain native. The peer installers
do not install the daemon or the vendor products. Relaunch/resume managed
sessions after updating so their helpers load the new build.

## Known limits and preview scope

Daemon connection loss ends a Worker and its retained results for every product;
it is not an instruction to replay an interrupted action.

Pi and OMP's [acceptance record](https://github.com/sessionbus/pi-omp/blob/710e5d33369cba4fb9468cd24fea0fe844a0219d/docs/designs/pi-omp-0.5.0/ACCEPTANCE.md) distinguishes
installed observations from deterministic fixtures and lists the work before
removing preview status. Pi admitted interrupt/recovery and OMP staged delivery,
Forget and interactive context acceptance remain in that work. OMP dialog
cancellation and Task child behavior retain their fixture-only qualification.
No extra model call is required just to turn an already-assessed fixture failure
into a successful fixture exit.

Ambient extensions remain enabled. An OMP extension writing unrelated text to
RPC stdout can invalidate the managed connection. Native startup can migrate
legacy settings or keybindings and update bookkeeping. Neither a successful
launch nor an empty editor promises byte-identical native configuration.

Linux installed observations do not establish native macOS behavior. macOS
builds and CI fixtures are validated separately; native macOS acceptance remains
qualified by each product's recorded evidence.
